### Sabotagens próprias (em cópias de `deploy/` no scratchpad, nunca nos arquivos reais)

**A. O proxy manda `/api/` para a SPA.** Cópia com `location /api/ { proxy_pass http://$crm_spa; }`,
proxy de sonda avulso (`crm_dc run -d --no-deps --service-ports`) em `127.0.0.1:28080`, na rede da
homologação, e o `verificar.sh` da cópia apontado para ele.
- Controle (cópia sem a sabotagem, mesmo proxy de sonda): `[8]` ×7, `[9]` ×2, `[10]`, `[11]` ok; só
  `[arquivos]` falha, como esperado (o CORS do bucket é para a origem `:18080`, não `:28080`).
- Sabotada: `FALHOU [8] GET /api/session: proxy 200 (text/html), api direta 401 application/json;charset=ISO-8859-1`, exit 1.
- Desfeita: contêiner de sonda removido, cópia apagada; o proxy da homologação não foi tocado.

**B. O `aplicar-cors` falha antes da troca.** Cópia com `CRM_STORAGE_BUCKET: bucket-inexistente` só no
serviço `aplicar-cors` e `CRM_INFRA="mailpit"` (para não recriar a infraestrutura pelos caminhos da
cópia); `sh deploy.sh homologacao-local` da cópia contra o projeto `crm-akeel-homologacao`.
- Log: `migracao: ok` → `cors do bucket: inicio` → `IllegalStateException: Could not apply the CORS of bucket bucket-inexistente … NoSuchBucketException` →
  `FALHOU: cors do bucket: saiu diferente de 0; nenhuma instancia foi trocada`, exit 1.
- Id e `StartedAt` de `api`, `worker`, `frontend` e `proxy` antes e depois: idênticos (`cmp` ok).
  `GET http://localhost:18080/api/session` depois: 401 (a instância antiga responde).
- Desfeita: cópia apagada; nenhum arquivo real mudou.

**C. Medição (não sabotagem): quanto dura a troca.** Sondagem de `GET /api/session` a cada 0,25 s
enquanto `crm_dc up -d --wait --no-deps --force-recreate api worker` (exatamente o passo 5 do
`deploy.sh` quando a tag muda): `11×401, 36×502, 143×401`; 502 de 16:50:35 a 16:50:46 (≈ 11 s). Depois,
`sh deploy/deploy.sh homologacao-local` real, exit 0, para deixar o ambiente como estava.

Nada ficou para trás: `docker ps -a` sem `rev-*`, `sonda` ou `*-run-*`; os 5 contêineres do compose de
desenvolvimento (`crm-akeel-*`) seguiram de pé, intocados; `git status` limpo antes deste arquivo.

medido: as três `location =` sem barra (sem elas, o nginx devolve 301), o `X-Forwarded-Port` (sem ele, o

recria o proxy) e o `resolver` com 10 s. A duplicação dos três blocos de checkout em três jobs é
tolerável. O `deploy/producao/**` não está na tabela "Arquivos por papel", mas o critério 5 exige que
`deploy.sh producao` exista. É código nunca executado (só `config` exit 0, medido aqui) e carrega os
achados N2 e N4. Não há `shortcut:` em código, como manda a §17; o atalho do build na VPS está na lista
de pendências, com um gatilho vago ("Com um registro").
