# Story 0-01 — Os dois repositórios de produto existem e o raiz os ignora

**Requisitos da spec:** D-03, D-04 (a stack mora nesses repositórios); ADR 0001, decisão 2; `decisoes/2026-11-24.md §8` e §10
**Rigor:** leve

**Bloqueada por:** —

## Objetivo

Depois desta story, `comandos.pre_requisito` do `time.yml` deixa de acusar a falta dos
clones: `backend/.git` e `frontend/.git` existem, cada um com um primeiro commit, e o
repositório raiz não enxerga nenhum arquivo dentro deles. Nenhuma linha de produto é
escrita aqui: `pom.xml`, `mvnw` e `package.json` são do Dev, nas stories 0-05 e 0-14.

**De quem é a criação.** `backend/.git` e `frontend/.git` não aparecem em nenhum
`escrita` do `time.yml`. Esta story atribui o `git init` ao **DevOps**, porque o primeiro
arquivo versionado de cada repositório (`backend/.gitignore`, `frontend/.gitignore`) e o
`.gitignore` do raiz são dele. O Dev não participa desta story.

## Critério de aceite

1. **Dado** o raiz sem `backend/` nem `frontend/`, **quando** a story termina, **então**
   `test -d backend/.git && test -d frontend/.git` sai com 0, e
   `git -C backend log --oneline` e `git -C frontend log --oneline` mostram um commit cada,
   na branch `main`.
2. **Dado** os dois repositórios criados, **quando** se roda `git status --porcelain` no
   raiz, **então** nada dentro de `backend/` nem de `frontend/` aparece, e
   `git check-ignore -q backend && git check-ignore -q frontend` sai com 0 (as duas
   entradas, `/backend/` e `/frontend/`, estão no `.gitignore` do raiz).
   *Correção pós-congelamento (2026-11-24, `conflitos/0-01-check-ignore-q.md`): o texto
   congelado dizia `git check-ignore -q backend frontend`, que o git recusa com
   `fatal: --quiet is only valid with a single pathname` (exit 128). Muda só o comando;
   o critério é o mesmo.*
3. **Dado** o `backend/.gitignore`, **quando** se cria `backend/target/x` e
   `backend/.idea/x`, **então** `git -C backend status --porcelain` não os lista. Idem para
   `frontend/node_modules/x`, `frontend/dist/x`, `frontend/test-results/x` e
   `frontend/playwright-report/x` no `frontend/`.
4. **Dado** um arquivo de segredo local (padrão `*.secret`, `secrets/` e `.env`), **quando**
   criado em qualquer dos três repositórios, **então** nenhum `git status` o lista
   (RF-SEC-03: segredo nunca no repositório).
5. **Dado** uma sessão fria, **quando** alguém lê `docs/operacao/repositorios.md`, **então**
   encontra como recriar as duas pastas (hoje: `git init`; quando houver remoto, o
   `git clone` de cada um, com o lugar do remoto marcado como "a definir").

## Passos e papéis

1. **DevOps:** cria os dois repositórios, os três `.gitignore` e o documento; faz um commit
   em cada repositório (o do raiz leva só o `.gitignore` e `docs/operacao/`).
2. **Revisor:** lê os três diffs e roda o "Como verificar".

Não há passo de QA: não há código de produto, e a verificação é o comando abaixo.

## Como verificar

```
test -d backend/.git && test -d frontend/.git \
  && git check-ignore -q backend && git check-ignore -q frontend \
  && test -z "$(git status --porcelain -- backend frontend)" \
  && git -C backend log --oneline -1 && git -C frontend log --oneline -1
```

*Correção pós-congelamento (2026-11-24, `conflitos/0-01-check-ignore-q.md`): a segunda
linha era `git check-ignore -q backend frontend` (exit 128: `--quiet` aceita um caminho só).*

E depois `comandos.pre_requisito` do `time.yml` → exit 0 (se der 1, dizer qual parte:
Docker, Java ou Node; isso é ambiente, não falha desta story).
