## Objetivo

O workflow de CI do backend existe e cada passo dele roda localmente pelo mesmo comando, e
o `backend/Dockerfile` produz **uma** imagem que serve aos três modos (`api`, `worker`,
`migrate`, este último entra em 0-10).

## Critério de aceite

1. **Dado** `backend/.github/workflows/`, **quando** se roda o actionlint por contêiner,
   **então** sai com 0.
2. **Dado** o workflow, **quando** se lê, **então** os passos são, nesta ordem:
   `./mvnw -B verify` (que já inclui arquitetura e Testcontainers, com Docker no runner);
   análise de dependências (OWASP Dependency-Check ou equivalente) que **falha** com
   vulnerabilidade de severidade alta ou crítica; build da imagem. O passo 1 é exatamente
   `comandos.suite_backend`.
3. **Dado** a máquina local, **quando** se rodam os comandos de cada passo do workflow, na
   ordem, **então** todos saem com 0. Se a análise de dependências precisar de chave de API
   (ex.: NVD) e ela não existir localmente, o DevOps registra isso e o critério vale para os
   outros dois passos; o que falta vai para as pendências da onda, não é contornado.
4. **Dado** `docker build backend/`, **quando** termina, **então** a imagem roda como
   usuário não root, não contém o código-fonte nem o diretório `target/` inteiro, e sobe com
   a aplicação respondendo à verificação de saúde contra o PostgreSQL do compose (0-02).
5. **Dado** a imagem, **quando** se procura credencial nela (`docker history`, variáveis de
   ambiente), **então** não há nenhuma (RF-SEC-03).

