# ADR 0004 — O AG-UI não entra na v1; entra junto com o assistente de IA, quando a spec o trouxer para dentro do CRM

Dono: Arquiteto. Data: 2026-11-24. Estado: aceito pelo humano em 2026-11-24 (`planning/decisoes/2026-11-24.md` §15)

Pedido em `planning/decisoes/2026-11-24.md §12` ("Avalie o uso do
ag-ui-protocol/ag-ui para o frontend").

## Contexto

**O que o AG-UI é** (conferido em 2026-11-24):

| Fato | Evidência |
|---|---|
| Um **protocolo** de eventos entre um **agente de IA** e a interface do usuário: o app manda um `RunAgentInput` (mensagens, ferramentas, estado) e o agente devolve um fluxo de eventos tipados (31 tipos: texto em streaming, chamada de ferramenta, estado compartilhado, raciocínio, subagentes). Transporte HTTP + SSE ou HTTP + Protobuf | `README.md` do repositório (branch `main`); spec em docs.ag-ui.com/spec/1.0 |
| **Exige um agente do outro lado.** "An AG-UI agent is any HTTP endpoint that accepts a `RunAgentInput` and streams events back". Sem agente (e sem um LLM por trás dele), não há o que conectar | `README.md`, "Quick start"; os modelos do `create-ag-ui-app` "call OpenAI" e pedem `OPENAI_API_KEY` |
| Ocupa a camada "agente para usuário"; o **MCP** é a camada "agente para ferramentas e dados", e um mesmo agente costuma usar os dois | `README.md`, "Where AG-UI fits" |
| Licença MIT; criado pela CopilotKit; 21.510 estrelas; repositório de 2025-05-07, não arquivado, último push 2026-11-24 | `api.github.com/repos/ag-ui-protocol/ag-ui` |
| Spec **1.0 congelada**, com JSON Schema; SDKs oficiais TypeScript, Python e .NET. `@ag-ui/client` 1.0.5 no npm (MIT), que puxa `rxjs`, `fast-json-patch`, `@ag-ui/proto` e outros | `README.md`; `registry.npmjs.org/@ag-ui/client/latest` |
| Releases muito frequentes (20 entre 2026-10-09 e 2026-11-21), com quebras nos adaptadores: `release/2026-11-21` traz "Breaking changes" em `@ag-ui/langgraph` e corrige um desvio de autenticação em `ag_ui_adk` (GHSA-jhvp-j8pf-5vh5) | `api.github.com/repos/ag-ui-protocol/ag-ui/releases` |
| **Java só existe como SDK comunitário**, fora dos oficiais: `com.ag-ui.community:java-core` 0.1.1 e os starters Spring (`ag-ui-spring-webmvc-boot-starter` 4.1.0, publicação única em 2026-09-16), que acompanham o **Spring Boot 4.1.x**; o nosso é 4.2.x (ADR 0001). Pacote Java `com.agui` | `README.md`, "Community SDKs"; `sdks/community/java/spring/README.md`; `repo1.maven.org/maven2/com/ag-ui/community/*/maven-metadata.xml` |
| O cliente de React em destaque é o **CopilotKit** (o `create-ag-ui-app` gera Next.js); nosso front é SPA Vite (D-04) | `README.md`, "Quick start" e "Clients" |

**O que a spec diz** (`especificacao-crm-akeel-v1.1.md`):

- §3.3, linha 235: "assistente de IA" está **fora da v1**.
- §15, linha 2049: "Assistente de IA | Resumo de conversas e sugestão de próximo passo;
  **o MCP (RF-API-15) é o caminho para IA externa**".
- §10.7, RF-API-15 (Could): servidor MCP com OAuth, com as permissões do usuário, sem
  ferramentas de exclusão. "Pode ficar para depois da v1."
- Nenhum requisito da v1 pede LLM, chat com agente ou interface gerada por agente.

## Decisão

**Não adotar o AG-UI na v1.** Ele não resolve nenhum requisito da v1: é a interface de um
agente que a v1 não tem, e o único caminho de IA que a spec prevê (RF-API-15, MCP) é o
contrário, um agente **externo** operando o CRM, sem tela nossa.

**Custo de adotar agora**, todo sem requisito que o pague:
- um **servidor de agente** e um **provedor de LLM**: peça nova no Compose (ou o agente
  dentro do `api`), chave e cobrança de terceiro;
- **dados de clientes indo para um provedor de LLM**, o que toca LGPD (rigor completo) e
  a RNF-14 (dados no Brasil): é decisão da Akeel, não do time;
- no backend, um SDK **comunitário** 0.1.x / 4.1.0, um release só, atrás da nossa versão
  do Boot; ou um agente em Python/TS ao lado do monólito, o que quebra D-03;
- no front, `@ag-ui/client` e, na prática, o CopilotKit, num projeto que solta releases
  com quebra toda semana.

**Gatilho:** o Pedro trazer o "assistente de IA" de §15 para dentro do CRM (resumo de
conversas, sugestão de próximo passo, chat dentro da tela), **com** a decisão da Akeel
sobre qual provedor de LLM pode receber dados de clientes. Aí este ADR é substituído, e
o AG-UI é a escolha natural para a camada de tela, com o agente usando as mesmas
ferramentas do MCP (RF-API-15).

**O que fica preparado hoje, sem custo:** nada de código nem dependência. O que já está
decidido é exatamente o que um agente AG-UI usaria depois: SSE como transporte de tempo
real (§4.2), a BFF com cookie de sessão (ADR 0003, o front chamaria o agente pela BFF sem
token no navegador) e as operações com permissão do usuário que o MCP vai expor. Só uma
regra: quando o RF-API-15 for construído, as ferramentas do MCP devem chamar os mesmos
serviços de aplicação que a API REST, sem lógica própria; é isso que deixa um assistente
interno barato depois. Vale para a story do RF-API-15, não para agora.

## Alternativas consideradas

| Alternativa | Por que não agora | Gatilho que a faria valer |
|---|---|---|
| **AG-UI agora, com o SDK Spring comunitário dentro do `api`** | Nenhum requisito da v1; SDK 0.1.x de comunidade, um release, acompanha Boot 4.1 e nós usamos 4.2; exige provedor de LLM e decisão LGPD | O gatilho da decisão, mais o SDK Java acompanhar a linha do Boot que usarmos (ou virar oficial) |
| **AG-UI agora, com agente em Python/TS ao lado do monólito** | Tudo o que está acima, mais um segundo runtime no Compose, o que contraria D-03 (um artefato) | O gatilho da decisão, se o agente precisar de um framework que só existe em Python/TS |
| Chat próprio sobre o SSE que já teremos (a mais barata, se o gatilho vier) | Também não tem requisito na v1 | O assistente vir com escopo pequeno (só resumo, sem ferramentas nem estado compartilhado). Com ferramentas, interrupções e estado, o AG-UI fica mais barato que reinventá-lo |
| **MCP (RF-API-15)** | Não é alternativa ao AG-UI: é a camada de ferramentas, e já está na spec como Could | O que a spec já diz |

## Guardado por

Não é regra de camada; é uma dependência que não entra. Asserção proposta para o
`ArchitectureTest` quando ele nascer (Onda 0), em `comandos.arquitetura`: nenhuma classe
depende de `com.agui..` (pacote do SDK Java). No frontend, o Revisor trata qualquer
`@ag-ui/*` ou `@copilotkit/*` no `package.json` sem ADR que substitua este como achado.

## Consequências para o time

Nenhuma mudança em comandos, caminhos ou `time.yml`. A spec não muda. Aceito pelo
Pedro (§15): `@ag-ui/*`, `@copilotkit/*` e `com.ag-ui.community:*` ficam fora até o gatilho.
